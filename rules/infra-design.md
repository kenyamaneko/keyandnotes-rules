# インフラ設計

Key and Notes 各プロジェクト共通のインフラ設計規約。`principles.md` から参照される。クラウドごとのサービスの使い分けは `rules/cloud/<cloud>.md` が定める。

## IaC

- クラウド上のリソース (例: ネットワーク・実行基盤・データストア・権限・監視・予算アラート) は IaC で定義する
- アプリの版 (コンテナイメージ・環境変数) の反映は、IaC ではなくデプロイのパイプラインが行う
  - なぜ: コミットのたびに変わる値を IaC に置くと、デプロイのたびに IaC の反映が要るため
- 環境 (dev・stg・prod) は、同じモジュールを呼び出し側の変数だけ変えて作る
- 環境ごとにクラウドのプロジェクトを分ける
- IaC の state は、変更されるタイミングと権限の境界で分ける (例: 環境ごとのリソースと、環境をすべて消しても残す運用ツールは別の state にする)

## コスト方針

- 新しいシステムを立ち上げるときは、実装に着手する前に、コスト方針 (月の予算の上限、非稼働時のコスト発生を許容するか) をユーザーに確認し、BDR に残す
- コスト方針が非稼働時のコスト発生を許容しないときは、次のとおりにする
  - 従量課金のサービスが使えるなら積極的に検討する
  - 未使用時にも課金される構成要素 (例: ロードバランサー) は、使わないときに動的に落とす仕組みを検討するか、使わない
- 予算アラートを環境ごとのプロジェクトに 1 つずつ置く
- 利用回数に応じて課金される外部 API (例: 生成 AI) の呼び出しには、アプリ層で利用回数の上限を設ける

## 権限と認証

- CI からクラウドへは、短命トークン (ID 連携) で認証する

## 監視

- 監視対象は、メトリクスと、そのメトリクスがしきい値を超えたときに通知するアラートの組で定める
- 実行基盤のリソース (サービス・ジョブ・データベース) を追加する変更には、そのリソースのメトリクスとアラートの追加を含める
- メトリクスとアラートは、リソースの一覧をもとに、IaC のループでまとめて定義する
- 必須の監視対象は以下の通り。いずれもメトリクスとアラートを設ける
  - サービス: 要求の失敗 (5xx)、ERROR ログ
  - ジョブ: 実行の失敗
  - データベース: CPU・メモリ・ディスクの使用率、同時接続数
  - 費用: 環境ごとの予算
- 上記以外にも、システムの特性に応じて、メトリクスとアラートを追加する
- dev も監視の対象にする

## データ保護

- 本番のデータストアには、バックアップ手段を設ける
- 本番のデータストアに削除保護をかける
