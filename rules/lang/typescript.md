## [lang/typescript] ディレクトリ構成 (フロントエンド)

- 実装はソースのルートに置く
- アーキテクチャ上の役割の名前は system-design.md「クリーンアーキテクチャと役割の名前」に従う。`adapter` には、ブラウザ API (例: ファイルのダウンロード)・ファイル形式との接続も置く。TypeScript 固有の役割は次のとおり。使わないものは作らなくてよい
  - `components`: 画面部品
  - `constants`: 送料無料の閾値・テーマ色など、複数の場所で使う定数
  - `hooks`: React のカスタムフック
  - `state`: 画面をまたいで共有する状態 (例: カートの中身)
  - `utils`: 業務に依存しない汎用処理
- テストファイル (`*.test.ts` / `*.test.tsx`) は、対象ファイルと同じディレクトリに置く。複数のテストで共有する部品 (セットアップ・描画・モックサーバー) は `test` にまとめる

## [lang/typescript] ディレクトリ構成 (バックエンド)

- 実装はソースのルートに置く
- アーキテクチャ上の役割の名前は system-design.md「クリーンアーキテクチャと役割の名前」に従う。TypeScript 固有の役割は次のとおり。使わないものは作らなくてよい
  - `middleware`: 認証・レート制限など、複数の `presentation` に共通する前処理
  - `utils`: 業務に依存しない汎用処理 (例: ロガー)
- テストファイル (`*.test.ts`) は、対象ファイルと同じディレクトリに置く。複数のテストで共有する部品 (ダミーデータ・差し替え部品) は `test` にまとめる

## [lang/typescript] テスト方針

- テストランナーは Vitest を用いる (backend / frontend 共通)
- GUI テストの原則は testing.md「GUI (画面) のテスト」に従い、次のツールで実装する
  - React コンポーネントは Testing Library (`@testing-library/react` + `@testing-library/user-event`) で操作する
  - API 通信のモックは MSW で HTTP 境界 (ネットワーク層) をモックする。api クライアント / モジュールを `vi.mock` 等で直接差し替えない
- データ駆動は `it.each` でケース化する
- テストの命名は testing.md「テストの命名」を次のとおり割り当てる
  - `[区分:大機能(:中機能)]小機能` = 最も外側の `describe` (例: `describe("[本体:注文:業務ルール]送料計算")`)
  - ケース = 項目を引数に取る補助関数 (`defineCase`) の呼び出し。補助関数がテスト名を組み立て、項目を Vitest の注釈 (`annotate`) として結果に載せる。Playwright の E2E では、`annotations` に積む。必須の項目は型で必須にする
    - 例 (1 ステップ): `defineCase({ 種別: "単体テスト", 正常異常: "正常系", steps: [{ Given: "注文金額が3000円のとき", When: ["注文画面の送料の計算で、送料を計算する"], Then: "送料は無料になる" }] }, () => { ... })`
    - 複数ステップのケースは、ステップの検証を `steps` の各要素の `Then` に対応させ、本体の中でステップごとに確かめる
    - 注釈のキーは `Given`・`When`・`Then`・`種別`・`正常異常`。ステップは、`Given` (省略可)、`When` (手順の数だけ)、`Then` の順に繰り返して載せる。順序は保たれる
    - なぜ: Vitest と Playwright の JUnit 出力は、注釈を `<property>` として、載せた順に出力する。テストのタグは出力しない
  - テーブル駆動は、行ごとに `defineCase` を呼ぶ
  - 注釈はテストの実行中に付くため、スキップしたテストには付かない

## [lang/typescript] docs コメント

- docs コメントは TSDoc (`/** ... */`) 形式で書く。`@param` / `@returns` は、型から読み取れない情報 (単位・制約・null や省略時の意味・副作用など) がある引数・戻り値にのみ書く

## [lang/typescript] 命名

- get アクセサ (get x()) は動詞を付けず対象名にする
- フレームワーク固有の命名慣用 (コンポーネント名・フック名等) はそのフレームワークの規約を優先する

## [lang/typescript] 分岐

- `switch` には必ず `default` 節を書き、想定外の値として throw する。空の `default` で無言に通過させない
  - ユニオン型の分岐では、値を `never` 型の引数で受ける関数 (assertNever) を `default` で呼び、コンパイル時の網羅性チェックと実行時の早期失敗を両立させる

## [lang/typescript] 変数宣言

- `var` を使わない (`const` を基本とし、再代入が必要な場合のみ `let` を使う)
