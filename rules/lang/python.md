## [lang/python] ディレクトリ構成

- 実装はパッケージに置く。実装のディレクトリを分けないときは、モジュールをパッケージの直下に置く
- アーキテクチャ上の役割の名前は system-design.md「クリーンアーキテクチャと役割の名前」に従う
- テストは実装とは別の `tests` に、実装と同じ構成で置く。ファイル名は `test_<対象のモジュール名>.py` にする。複数のテストで共有するフィクスチャは `conftest.py` に置く

## [lang/python] docs コメント

- docs コメントは Google スタイルの docstring 形式で書く。`Args:` / `Returns:` セクションは、型から読み取れない情報 (単位・制約・null や省略時の意味・副作用など) がある引数・戻り値にのみ書く

## [lang/python] テスト方針

- テストは pytest を用いる
- データ駆動は `@pytest.mark.parametrize` でケース化する
- テストの命名は testing.md「テストの命名」を次のとおり割り当てる
  - `[区分:大機能(:中機能)]小機能` = 最も外側のテストクラス名。`Test` に続ける (例: `class Test本体__注文__送料計算:`)。pytest は `Test` で始まるクラスを集める
    - `[区分:大機能(:中機能)]` と小機能は、`[` `]` `:` を外し `_` 2つでつなげて書く (例: `class Test本体__決済__クレジットカード決済__与信判定:`)。`[` `]` `:` はクラス名に使えず、`_` 1 つでは読点・空白の置き換えと区別できないため
  - ケース = テスト関数名。`test_` に続ける (例: `def test_注文金額3000円で送料を計算すると_送料は無料になる():`)
  - ケースの項目 = `record_property("Given", "...")` を呼ぶ補助関数。キーは `Given`・`When`・`Then`・`種別`・`正常異常`・`観点`。`観点` は省略可で、観点ごとに `record_property("観点", "境界値")` を 1 回ずつ呼ぶ。ステップは、`Given` (省略可)、`When` (手順の数だけ)、`Then` の順に繰り返して呼ぶ。項目は JUnit XML の `<property>` に、呼んだ順に出る
  - クラス名・関数名では、読点・空白・ステップの区切りの「→」は `_` に置き換え、それ以外の記号は除く
    - `order_id` と `order id` のように区切りだけが違う語は、同じ語として扱う
      - なぜ: テストケースカタログでは `_` が空白に戻るので、`_` を含むキー名は関数名と `id` で必ず形が変わるため
    - 記号を除くと意味が変わる値 (負の数・小数など) は、記号を言葉に置き換える (例: `-1` は「マイナス1」)
  - `parametrize` のケース = `pytest.param` の `id`。関数名はカタログに出ないため英語でよい
- 日本語の id は既定で `\uXXXX` 形式にエスケープされて読めなくなるため、pytest の設定で `disable_test_id_escaping_and_forfeit_all_rights_to_community_support = True` を設定する

## [lang/python] 命名

- @property は動詞を付けず対象名 (名詞) にする
- pytest のフィクスチャは、値を返すものは名詞にし、関数を返すものは動詞で始める
