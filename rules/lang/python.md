## [lang/python] ディレクトリ構成

- 実装のディレクトリを分けるときは、すべてアーキテクチャ上の役割で分ける。分けないときは、モジュールをパッケージの直下に置く
- 名前は次を参考にする。使わないものは作らなくてよい
  - `adapters`: 決済代行会社・配送業者など、外部サービスとの接続
  - `core`: 送料計算・会員ランク判定などの業務ロジックと型
  - `services`: 注文確定など、複数の処理をつなぐ業務の操作
  - `handlers`: 外部からの呼び出しの受付
  - `jobs`: バッチ処理などの起動の入口
- テストは実装とは別の `tests` に、実装と同じ構成で置く。ファイル名は `test_<対象のモジュール名>.py` にする。複数のテストで共有するフィクスチャは `conftest.py` に置く

## [lang/python] docs コメント

- docs コメントは Google スタイルの docstring 形式で書く。`Args:` / `Returns:` セクションは、型から読み取れない情報 (単位・制約・null や省略時の意味・副作用など) がある引数・戻り値にのみ書く

## [lang/python] テスト方針

- テストは pytest を用いる
- データ駆動は `@pytest.mark.parametrize` でケース化する
- テストの命名は testing.md「テストの命名」を次のとおり割り当てる
  - 大分類 = 最も外側のテストクラス名。`Test` に続けて日本語で書く (例: `class Test注文__送料計算:`)。pytest は `Test` で始まるクラスを集める
    - 大分類の `[...]` と本体は、`[` `]` を外し `_` 2つでつなげて書く (例: `class Test注文__送料計算:`)。`[` `]` はクラス名に使えず、`_` 1 つでは読点・空白の置き換えと区別できないため
  - 各ケースの名前 = テスト関数名。`test_` に続けて日本語で書く (例: `def test_注文金額が3000円のとき_送料は無料になる():`)
  - 小分類 = 入れ子のクラス名。`Test` に続けて日本語で書く
  - 正常異常 = 大分類とケースの間のどこかに重ねる入れ子のクラス名。`Test` に続けて「正常系」「異常系」と書く
  - クラス名・関数名では、読点・空白は `_` に置き換え、それ以外の記号は除く
    - `order_id` と `order id` のように区切りだけが違う語は、同じ語として扱う
      - なぜ: テスト観点カタログでは `_` が空白に戻るので、`_` を含むキー名は関数名と `id` で必ず形が変わるため
    - 記号を除くと意味が変わる値 (負の数・小数など) は、記号を言葉に置き換える (例: `-1` は「マイナス1」)
    - パスや日時のように、記号を言葉に置き換えても読めない値は、具体値の代わりにその値が何であるかを書く (例:「保存先が `2026-09-26T03:15:00Z.json` になる」ではなく「保存先のファイル名が作成した日時になる」)
  - `parametrize` では 1 つの関数が複数のケースを持つため、割り当てを一段ずらす。関数名にはテーブル全体で共有される操作 (When) を `test_` + 日本語で書き、各ケースの名前 (Given + Then) は `pytest.param` の `id` に日本語で書く
  - 同じクラスに When が同じテーブルが複数あると、関数名が重なって後に定義した方しか実行されないため、次のように分ける
    - 前提 (Given) の種類で分かれるときは、小分類として入れ子のクラスに分ける
    - 確かめる結果 (Then) の種類で分かれるときは、大分類が別なので最も外側のクラスを分ける
- 日本語の id は既定で `\uXXXX` 形式にエスケープされて読めなくなるため、pytest の設定で `disable_test_id_escaping_and_forfeit_all_rights_to_community_support = True` を設定する

## [lang/python] 命名

- @property は動詞を付けず対象名 (名詞) にする
- pytest のフィクスチャは、値を返すものは名詞にし、関数を返すものは動詞で始める
