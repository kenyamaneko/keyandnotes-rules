# デプロイ戦略 (Manual Local Apply)

CI を作らず、人がローカルで手動で反映する戦略。

## 環境とトリガー

| 環境 | トリガー |
|---|---|
| prod | `main` へのマージ後に、人がローカルで反映を実行 |

## ゲート

PR の lint (必須ステータスチェック) と、反映の前に人が実行計画の差分を確認することがゲート。

## 反映方式

- 実行するコミットは `main` のものに限る
  - なぜ: `main` に無い定義を反映すると、次に `main` から反映したときに、その定義のリソースが消えるため
- 認証は、実行者自身の認証情報で行う
- 同時に実行されないよう、state のロックを使う

## タグ・バージョニング

タグは使わない (state が SSoT のため)。

## ロールバック

取り消す変更を打ち消す内容の PR を `main` にマージし、`main` のコミットから反映し直す。

## 想定リポジトリ / 選定の目安

- 環境が一つで、運用者が一人の IaC
- 環境が複数、または運用者が複数のときは Manual Pipeline を検討する
